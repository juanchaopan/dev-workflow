# Node.js 规范：{{组件名}}

来源：typescript-eslint 推荐规则、Node.js 官方文档。格式由 Prettier 负责，类型和常见问题由 TypeScript 严格模式和 ESLint 检查；这里写需要判断的部分。

## 结构

- 分层：路由（接收请求、校验、返回）→ 服务（业务逻辑）→ 数据访问。路由里不写业务逻辑。
- 按功能分目录。用 ES 模块，相对导入写上 `.js` 扩展名（NodeNext 模块解析的要求）。

## 类型和校验

- 不用 `any`。外部输入（请求体、查询参数、环境变量、消息）在边界处用 schema 校验（例如 zod），校验后的类型再往里传。
- 配置在启动时一次性读取并校验，缺了就报错退出。

## 异步和错误

- 每个 Promise 都要 await 或显式处理（ESLint 的 no-floating-promises 会检查）。
- 错误统一由错误处理中间件转换成响应，不把堆栈返回给调用方。
- 调用外部服务都设置超时；只对幂等的操作做重试。
- 请求处理路径上不用同步的文件和加密 API（`readFileSync`、`pbkdf2Sync` 等），它们会卡住整个进程。

## 运行

- 日志用结构化日志库（例如 pino），每个请求带上追踪编号；不打印密码、令牌和完整的个人信息。
- 收到 SIGTERM 时优雅停机：停止接收新请求，处理完手上的再退出。
- 提供健康检查接口。
- 进程内不保存请求之间的状态，这样才能多实例部署。

## 测试

- 用 Vitest。服务层测业务逻辑；接口用框架自带的注入方式测（例如 Fastify 的 `inject`）或 supertest。
- 数据库用真实的测试实例，不用模拟的查询结果。
